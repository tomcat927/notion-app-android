## 三、核心发现

### 3.1 资源量：含代码块 vs 不含，无差异

| 笔记 | code | 末采样资源数 | 末采样 KB |
|---|---|---|---|
| 刷机全攻略 | 5 | 352 | 7,503 |
| 【全】邮箱账号数据 | 7 | 270 | 5,779 |
| **[]出租房（code=0）** | **0** | **983** | **14,686** |
| **图床app（code=2）** | 2 | **995** | **15,184** |

**无代码块的 `[]出租房` 反而加载了 983 个资源 / 14.7MB —— 比含 7 个代码块的邮箱数据（270 资源 / 5.8MB）多 3 倍以上。**
→ 资源量由**笔记整体内容规模**决定，与代码块无关。

### 3.2 决定性证据：最严重的网络停顿发生在【无代码块】笔记

用"集体同耗时"特征（多个不相关请求在同一毫秒级窗口返回）检测链路 stall：

| 采样 | 笔记 | code | 集体 stall | 停顿时长 |
|---|---|---|---|---|
| L1424 | **[]出租房物品放置的位置** | **0** | ⚠ **是** | **42.9s** |
| L1691 | 图床app开发 | 2 | ⚠ 是 | 69.5s |

`[]出租房`（**code=0**）的 stall 证据：
```
82852-*.js              = 42,991ms
getTranscriptionUsage   = 42,973ms
getEduVerificationData  = 42,886ms
getCustomerOffersReceived=42,885ms
getSubscriptionBanner   = 42,879ms
```
**5 个毫不相关的请求，耗时全部落在 42,879~42,991ms（相差 112ms）** —— 这不是"某个资源慢"，
而是**整条链路停顿了 42.9 秒后同时恢复**。

`[]出租房` 的 `totalMs` 达 **1,496,369ms（≈25 分钟累计）**，是全场最高 —— 而它 **code=0**。

### 3.3 本轮网络状况好于上一轮

| 轮次 | syncRecordValue 超时 |
|---|---|
| 17:13 轮（v1/v2 数据源） | **244 次** |

—— 说明链路抖动是**常态风险**，不是偶发。

### 3.4 一个待观察点

`【全】邮箱账号数据`（code=7）的 `open→commit = 14s`，是本次唯一超过 10 秒的。
但它的 `totalMs` 仅 26,608ms（很低），资源也少（270）。
→ 更像**单次 TTFB 高**（首次请求慢），而非代码块导致；需要更多样本才能定性。

## 四、结论

1. **在干净的同会话对照下，"含代码块"与"不含代码块"的笔记没有稳定差异。**
   - 资源量：无代码块的笔记反而更高（983 vs 270）
   - 最严重的网络停顿（42.9s）：发生在 **code=0** 的笔记上

2. **瓶颈是网络链路的集体 stall，与 block 类型无关。**
   证据 = 多个不相关请求在毫秒级窗口内**同耗时返回**（42,879~42,991ms），
   这是链路停顿后同时恢复的典型特征，任何单点资源慢都不会呈现这种模式。

3. **本轮 18 次 `syncRecordValue` 超时**（上轮 244 次）说明网络状况波动大，
   但**即便在本轮较好的状况下，仍有 42.9s / 69.5s 的 stall** → 代理链路是主要变量。

4. **v1/v2 的结论经用户实测验证后成立**，且这次的证据（无代码块笔记也 stall）比之前更强。

## 五、下一步建议

**P0：给 WebView 的 `app.notion.com` 流量优化链路**
- 在 `cf-pref-sub-gen/server.py` 为 `app.notion.com` 加独立策略（选低延迟节点/直连），
  实测 stall 是否减少。
- 复核 `MainActivity.applyWebViewProxy()`：不翻墙时应确保 `clearProxyOverride` 及时触发。

**P1：探针增强（提高可观测性）**
- 现在 perf 只能在 `onPageFinished` 后采一次 + 一次延迟采样。
- 建议增加：记录 `syncRecordValue` 的成功/失败/耗时分布（P50/P95），
  以及"页面上有多少 block 长时间未渲染"，直接定位是否真与代码块相关。

**P2：补样本**
- 3 篇读不到 block 的页面（京东云路由器刷机 / 测试777 / 远程日志专用openlist账号密码）
  需先在 Notion 加集成授权。
- 建议再跑一轮同样的清单，累积多轮以确认 `【全】邮箱账号数据` 的 14s 是偶发还是特征。
